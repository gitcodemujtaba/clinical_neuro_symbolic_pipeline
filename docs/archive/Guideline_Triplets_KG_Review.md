# Guideline Triplets — MoLLM Grounding KG Review

Reviewed 2026-08-07. Scope: `local_triplets_db2_v6/` (final curated triplets) and its full upstream pipeline in `triplets-rules-backup-data/` (`local_chunks_db2_v6` → `local_medcat_entities_db2_v6` → `local_grounded_chunks_db2_v6` → `local_triplets_db2_v6`). This is the deterministic evidence base Stage 3 (`mollm_ensemble.py`) is meant to retrieve from and cite against — the single most load-bearing artifact for the "trustworthy/grounded" claim in the thesis title. Findings below are from directly parsing all 76 triplet files programmatically, not sampling by eye.

---

## 1. The Working Process (traced end-to-end on one file)

Confirmed a clean 4-stage curation pipeline, one guideline document at a time:

1. **`local_chunks_db2_v6/`** — raw guideline text split into named sections/chunks (e.g. `kdigo-2012-aki-guideline-english_chunk_4_section_2_aki_definition.json`, containing `chunk_id`, `section_title`, `content`).
2. **`local_medcat_entities_db2_v6/`** — MedCAT run over each chunk, producing `snomed_cui`, `preferred_name`, `source_value`, `confidence_score`, and character offsets per detected entity.
3. **`local_grounded_chunks_db2_v6/`** — the original chunk text with MedCAT hits injected inline as `term [SNOMED: cui]` annotations, plus an `_snomed_injection_stats` block reporting how many of the entities found were "qualified" and injected (in the traced example: 77 found → 45 qualified → 45 injected).
4. **`local_triplets_db2_v6/`** — the final artifact: a JSON-LD graph (`@context` / `@graph`) of clinical concept nodes (`@id`, `@type`, `name`, `snomed`, `icd10`, `provenance`), each carrying a `rules[]` array of `{predicate, target, rationale, citation}` edges to other nodes.

This is a sound design — it mirrors exactly what `Databases.md` describes for the Memgraph guideline graph (`:Concept` nodes, guideline-relation edges) and gives every extracted fact a citation trail back to the source chunk, which is the right shape for Stage 3's "retrieve fact-grounded context" step. The pipeline mechanics are not the problem; the output quality from the extraction step is where the issues below live.

## 2. Corpus Scale

- **76 triplet files** covering **10 distinct guideline source documents**: KDIGO 2012 AKI, AHA/ACC/HFSA Heart Failure, ACEP Acute Heart Failure Syndromes (clinical policy), ACEP Community-Acquired Pneumonia, ACC/AHA Non-ST-Elevation ACS, ACC/AHA STEMI Reperfusion Therapy, GOLD (COPD) 2026 Pocket Guide, SSC 2021 Sepsis, Joint Commission National Patient Safety Goals + Universal Protocol, and the ESI (Emergency Severity Index) Handbook 5th ed.
- This is **broader than what `Implementation_Methodology.md` currently documents** — it lists only "KDIGO, AHA/ACC, GOLD, SSC, NPSG/ESI," which undersells the actual curated set (misses the ACEP AHF and CAP clinical policies and the separate NSTE-ACS/STEMI documents as distinct sources). Worth updating the doc to name all 10 — it's a stronger evidence base than currently credited, and a thesis examiner will want the full source list enumerated.
- **1,969 total concept nodes, 1,203 rule edges** across the corpus. All topically on-target for MIMIC-IV discharge notes — AKI, sepsis, HF, COPD, ACS/STEMI, pneumonia, and ED triage are exactly the conditions that dominate ICU/ED-adjacent discharge summaries.
- **Referential integrity is clean**: 0 of 1,203 rule `target` UUIDs are dangling within their own file. That's good engineering discipline for a hand/LLM-curated JSON-LD corpus this size.

## 3. Critical Issues (in priority order)

### 3.1 Roughly half the nodes aren't actually grounded to SNOMED
**974 of 1,969 nodes (49.5%) have `"snomed": "N/A"`.** Breakdown: Finding (382), Intervention (195), Condition (153), Acuity (125), Medication (59), Quantitative Threshold (59), Timeframe (1). This is the single most important finding for "grounding of MoLLM" specifically — the whole premise of Stage 3 is that the LLM is grounded against *deterministic, coded* clinical facts, not free text. A node with `snomed: "N/A"` is functionally just a text label with a JSON wrapper; it can't be reliably joined against the SNOMED hierarchy (Neo4j) or the OMOP vocabulary (DuckDB) the rest of the pipeline is built on, and it can't be reached by a query that walks the graph by SNOMED code. **Before this feeds Stage 3, decide explicitly**: either run a second-pass grounding attempt on these 974 nodes (many "Quantitative Threshold" and "Timeframe" nodes are inherently un-codeable and that's fine — but 382 ungrounded *Findings* and 153 ungrounded *Conditions* almost certainly should have SNOMED codes and are worth re-running through MedCAT or a normalization pass), or tag them as text-only/unreachable-by-code nodes so Stage 3's retrieval logic knows not to expect a code-based join to succeed for them.

### 3.2 Massive node duplication — same concept represented as many separate nodes
**73 of 76 files (96%) contain duplicate nodes for the same SNOMED code**, and **1,243 of 1,969 total nodes (63%) are redundant re-instantiations of a concept already present elsewhere in the same file.** In the traced KDIGO example, "Acute Kidney Injury" (`14669001`) appears as **six separate `Acuity` nodes**, each carrying exactly one rule, rather than one `AKI` node with six edges. This looks like an artifact of extracting triplets fact-by-fact (one node created per statement) rather than consolidating by entity afterward. Practically, this means: when this loads into Memgraph, either (a) each of those 76-file exports creates its own node per `@id` and the graph ends up with **thousands of duplicate `AKI` nodes** across the corpus — which breaks the entire premise of a queryable concept-centric graph — or (b) your ingestion script already plans to merge by `snomed` code, in which case say so explicitly, because `init_memgraph_guidelines.py` doesn't exist yet to confirm it. **This needs a `MERGE ... ON snomed` (or equivalent dedup pass before ingestion) rather than blind node creation from `@id`.** `@id` should be treated as a within-file provenance handle, not a graph identity.

### 3.3 Citations are frequently not verifiable quotes — undermines the planned `citation_verified` mechanism
Checked all rule `citation` fields (≥15 chars, 1,114 total) against their source chunk text using longest-common-substring containment: **526 (47%) are strong verbatim matches, 282 (25%) are partial/paraphrased, and 306 (27%) show low containment — including citations that are not quotes at all but meta-references**, e.g. `"Section 3, first sentence."` and `"Section 3, Levy et al study description."` (verified against the raw chunk — "Levy et al" does not appear as quoted text; the guideline chunk discusses a nitroglycerin dosing study without directly quoting it that way). `Provenance_Schema.md` and the MoLLM design both depend on a `citation_verified` check — comparing the LLM's cited evidence against the actual guideline text to catch hallucination. If ~27% of the *curated* citations in the source-of-truth graph are themselves not literal, checkable quotes, an automated verifier has nothing to check them against, and inconsistent citation formatting (verbatim quote vs. paraphrase vs. section-pointer) will produce unpredictable false-negative "unverifiable" flags downstream. **Recommend normalizing every citation to a genuine contiguous excerpt of the source chunk** (or explicitly splitting the field into `citation_quote` (verbatim) vs `citation_note` (curator's paraphrase/pointer) so Stage 3 knows which one it can programmatically verify against).

### 3.4 Predicate vocabulary has near-duplicate/inconsistent relation types
30+ distinct predicates observed. Most are well-formed and clinically meaningful (`INDICATES` 482, `REQUIRES_INTERVENTION` 299, `TRIGGERS_SEVERITY` 149, `REQUIRES_MEDICATION` 75) — this is a genuine strength, far more expressive than the generic `GUIDELINE_RELATION` placeholder `Databases.md` currently describes, and worth preserving as real edge types in Memgraph rather than collapsing them. But there's schema drift: `NOT_RECOMMENDED_FOR` (3 occurrences) and `SUGGESTS NOT USING` (3 occurrences, with a literal space in the name) appear to mean the same thing; `quantitative_threshold` is used inconsistently as **both** an `@type` (26 nodes) and a predicate name (26 edges), while a separately-cased `Quantitative Threshold` (40 nodes) is also used as a type. **Recommend a predicate/type canonicalization pass** before ingestion — a fixed enum for predicates and node types, with a mapping table for the handful of near-duplicates found.

### 3.5 `icd10` field is 100% unpopulated
All 1,969 nodes carry `"icd10": "N/A"`. Not necessarily a defect (SNOMED is the primary grounding code, per the proposal), but it's dead weight in the schema as-is, and cheap to fix: the DuckDB `athena_concept_relationship` table (Athena/OMOP) typically carries SNOMED→ICD10CM "Maps to" relationships, so this could be backfilled programmatically from data you already have rather than left permanently blank — useful if you ever want to cross-reference against ICD-coded cohorts.

### 3.6 Minor
- 8 nodes are missing the `snomed` field entirely (distinct from the 974 with literal `"N/A"` — these have no key at all). Small in number, worth a schema-validation pass regardless.
- Two nodes have no `@type` at all.

## 4. What's Genuinely Good Here

- The **4-stage curation pipeline (chunk → MedCAT → SNOMED-injected grounding → JSON-LD triplets) is a sound, reproducible design** and is more rigorous than a lot of "LLM reads a PDF and outputs triples" approaches — the MedCAT-based grounding-before-triplet-extraction step is a real methodological strength worth calling out explicitly in the dissertation.
- **Predicate richness** (`INDICATES`, `TRIGGERS_SEVERITY`, `REQUIRES_MEDICATION`, `REQUIRES_INTERVENTION`, etc.) captures real clinical decision logic, not just generic "related to" edges — this is exactly the kind of structured, multi-relational representation your literature review cites as the reason KGE approaches like CompGCN outperform flat/random-walk embeddings.
- **Guideline coverage is broad and clinically on-target** for the MIMIC-IV note population, and broader than currently documented.
- **Within-file referential integrity is perfect** — no broken edges.

## 3.7 Addendum — MedCAT injection-stage noise, traced from a worked example (2026-08-07)
Inspected `local_grounded_chunks_db2_v6/acute_heart_failure_syndromes_critical_question_2_diuretics_...json` in detail (359 entities found, 152 qualified/injected — a 42% qualification rate, vs. 58% in the earlier-traced KDIGO chunk). This surfaced a source of noise one stage *upstream* of the triplet-extraction issues in §3.1–3.4 — i.e., in the MedCAT entity-linking/injection step itself, before any triplet is ever generated:

- **Bibliographic/page-header text is being coded as if it were clinical content.** The chunk contains `"...e38 Annals of Emergency Medicine [SNOMED: 773568002] Clinical Policy..."` — a running journal header from the PDF extraction, not a clinical statement, tagged with a SNOMED code as though "Annals of Emergency Medicine" were a clinical concept. This isn't a one-off: a corpus-wide scan found this exact pattern (`"Annals of Emergency Medicine [SNOMED: ...]"`) **39 times** across the grounded chunks, and **25 of the 96 grounded-chunk files (26%) contain citation/methodology boilerplate** (page headers, "Key words/phrases for literature searches," "Study Selection:" paragraphs) — concentrated in the ACEP/ACC clinical-policy-style documents (Acute HF Syndromes, Community-Acquired Pneumonia, NSTE-ACS, STEMI Reperfusion), which include full systematic-review methodology sections, unlike the more direct-recommendation style of KDIGO/GOLD/SSC.
- **Likely homonym collisions between statistical/methodological and clinical senses of the same word**, worth spot-checking against the loaded SNOMED KG: `"95% confidence [SNOMED: 225487001] interval"` (statistical confidence interval, not a clinical "confidence" finding) and `"After grading [SNOMED: 246228008] for methodologic rigor"` (grading of study quality, not a clinical grading scale) both got tagged inline. If these resolve to clinical-sense SNOMED concepts, they're mislinked homonyms that will introduce false context into anything that later retrieves "confidence" or "grading" from this KG.
- **The same phrase is linked inconsistently depending on where it appears.** `"emergency department [SNOMED: 225728007]"` is tagged as a single concept in the question stem, but later in the same chunk's keyword list, `"emergency [SNOMED: 409971007] department"` splits into two tokens with `department` left untagged — and `"emergency"` alone carries **three different SNOMED codes** in one chunk (`25876001`, `409971007`, `773568002` — the last being the journal-header mislink above).
- **Qualification rate (entities found → entities injected) varies widely and is likely a real contributor to the 49.5% ungrounded-node rate in §3.1**: 21%–78% across the 96 grounded chunks, averaging 46%. A concept MedCAT found but didn't clear the qualification threshold for never gets a `[SNOMED: ...]` tag injected into the text — which means when the triplet-extraction step later reads that chunk, it has nothing to anchor a code to for that concept, and plausibly ends up emitting a `snomed: "N/A"` node for something MedCAT actually *did* detect, just below whatever confidence cutoff "qualified" uses. Worth pulling that threshold and checking whether it's excluding good matches unnecessarily — this could meaningfully move the needle on §3.1 before even touching the backfill script.

**Recommendation:** strip non-clinical boilerplate (running headers/journal names, literature-search-methodology paragraphs, "Study Selection" statistics narrative) out of chunks before they're run through MedCAT. This is a cheap, mechanical preprocessing step — a handful of regex/heuristic filters — and doesn't require touching the MedCAT model or thresholds at all, unlike the qualification-rate question above, which needs the actual threshold value inspected first.

## 5. Recommended Fix Order (feeds into `Implementation_Checklist.md`)

1. **Node consolidation / merge-by-`snomed` before or during Memgraph ingestion** (§3.2) — this blocks everything else being queryable correctly, and is the highest-leverage fix since it's a data-processing step, not new extraction work.
2. **Decide and document the grounding policy for the 974 `N/A`-snomed nodes** (§3.1) — re-run grounding, or explicitly mark as text-only.
3. **Split/normalize the `citation` field** into verifiable-quote vs. curator-note (§3.3) before wiring up Stage 3's hallucination-detection citation check — otherwise that check will be unreliable on ~27% of the KG from day one.
4. **Canonicalize the predicate/type vocabulary** (§3.4) — small, mechanical, but needed before Memgraph schema/queries are written against it.
5. Backfill `icd10` from OMOP `concept_relationship` if useful downstream (§3.5) — `scripts/backfill_guideline_grounding.py` now does this for every auto-accepted match; not yet run against a populated DuckDB.
6. **Strip bibliographic/methodology boilerplate before the MedCAT injection step** (§3.7) — cheap, mechanical, and reduces noise entering the grounding pipeline before it ever reaches the triplet stage. Also worth pulling MedCAT's "qualified" confidence threshold and checking whether it's excluding good-but-not-injected matches, since that's plausibly feeding directly into the §3.1 ungrounded-node count.
7. Update `Implementation_Methodology.md`'s guideline source list to the full 10 documents actually curated.

None of this is a rebuild — the curation methodology is right, and the raw material (1,969 nodes, 1,203 clinically meaningful rules, 10 guidelines) is a strong asset. The issue is that it's currently at "good LLM-assisted first pass" quality, not yet at "queryable, verifiable deterministic evidence base" quality, and Stage 3's entire hallucination-mitigation story depends on the latter.

## 6. Executed: `scripts/clean_local_triplets.py` (2026-08-07)

`data/local_triplets_db2_v6` was selected as the final KG source over `data/rules-llm` (see `Rules_LLM_Triplets_Review.md` — the LLM-generated corpus had better raw grounding but worse referential integrity and less consistent schema; structural soundness was weighted higher since the grounding gap is fixable and broken structure isn't as cheaply fixed after the fact).

Items 1, 3, and 4 from the fix order above (node consolidation, citation classification, predicate/type canonicalization) don't require the populated DuckDB, so they were implemented and **run against the full 76-file corpus**, not just designed. Non-destructive — output at `data/local_triplets_db2_v6_cleaned/`, originals untouched, full report at `data/cleaning_reports/clean_local_triplets_20260807_143942.json`.

**Results:**
- **272 duplicate nodes merged** (down from the original 1,243-instance estimate, because that earlier figure counted all `"N/A"`-coded nodes as if they were "duplicates of each other" — they aren't, and aren't safe to merge; this run only merges nodes sharing a *real* SNOMED code). Rule targets pointing at merged-away duplicates were rewritten to the surviving node; 33 rules that became self-loops as a result were dropped. Worked example: the KDIGO AKI chunk went from 16 nodes / 34 rules to 4 nodes / 24 rules, correctly consolidating all 6 duplicate "Acute Kidney Injury" nodes into 1.
- **Safety finding worth flagging explicitly**: an initial version of the merge logic that merged purely by SNOMED code (ignoring `@type`) incorrectly combined "Systolic blood pressure ≥160 mmHg" and "Systolic blood pressure <90 mmHg" into a single node, because both cite the same generic parent SNOMED code for "systolic blood pressure" despite representing clinically opposite thresholds. Fixed by only auto-merging when every duplicate in a group agrees on `@type`; groups that disagree (41 found — the BP pair above, plus several "suspected X" vs. confirmed "X" pairs) are left unmerged and tagged `quality_flag: same_snomed_type_mismatch_not_merged` for a human to resolve, rather than guessed at automatically. Worth a manual pass over these 41 before ingestion.
- **38 predicates and 26 types canonicalized** via a conservative, hand-reviewed mapping — only merged pairs unambiguously representing the same relation (`SUGGESTS NOT USING`/`RECOMMENDS NOT USING` → `NOT_RECOMMENDED_FOR`; `quantitative_threshold`/`REQUIRES_QUANTITATIVE_THRESHOLD`/`HAS_THRESHOLD` → `HAS_QUANTITATIVE_THRESHOLD`; `IS_DEFINED_BY` → `DEFINED_BY`). Direction-ambiguous pairs like `RECOMMENDS` vs. `RECOMMENDED_FOR` were deliberately left alone.
- **Citations reclassified**: 492 `verbatim`, 132 `paraphrase_with_recovered_excerpt` (a genuine verbatim excerpt was located in the source chunk and attached alongside the original paraphrase), 202 `paraphrase` (no strong excerpt recoverable), 213 `pointer_unverifiable`. Stage 3's `citation_verified` check can now branch on `citation_type` instead of treating all citations as equally checkable.
- **Boilerplate nodes/rules flagged** (not removed) with `quality_flag: likely_boilerplate` per the patterns identified in §3.7.
- **Referential integrity re-verified after all rewrites: 0 dangling targets**, checked programmatically rather than assumed — this matters because the merge/rewrite step is exactly the kind of operation that could silently introduce dangling edges if done carelessly.

**Still outstanding**: the actual SNOMED/ICD10 grounding backfill for the remaining `"N/A"` nodes needs `scripts/backfill_guideline_grounding.py` run against the populated `kg2_lexical_store.duckdb`, which only exists in the EC2 environment. That script now points at `data/local_triplets_db2_v6_cleaned/` by default, so it builds on top of this cleaning pass rather than the raw corpus. The 41 type-mismatch groups also still need a human decision before ingestion.
